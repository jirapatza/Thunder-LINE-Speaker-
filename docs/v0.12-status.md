# v0.12 — สถานะการเชื่อมต่อ

ตรวจ 20 พฤศจิกายน 2569: ยังไม่ผ่านเกณฑ์ v0.12 และยังไม่ได้เปิดใช้งานจริง

- GitHub main มีโค้ด v0.11 สำหรับรับเหตุการณ์ที่ลงลายเซ็น ส่งลิงก์รูปผ่าน FCM และอ่านภาพบนมือถือ
- Cloudflare Worker `line-oa-slip-speaker` มี bindings `SLIP_QUEUE`, `DEVICES`, `RESULT_CACHE`; ตรวจรายการ Secrets แล้วไม่พบรายการ และไม่พบตัวแปร `SLIP_PROCESSING_MODE` ใน bindings ที่อ่านได้ การตรวจนี้ไม่ยืนยันว่า Firebase หรือ LINE พร้อมใช้งาน
- ค้นหา `x-line-signature` และ `webhook` ใน GitHub ที่เชื่อมต่อแล้ว พบโค้ดในรีโพซิทอรีนี้ แต่ยังระบุ handler ของ LINE OA เดิมหรือยืนยันสิทธิ์แก้ handler ไม่ได้ ผลค้นหาไม่ยืนยันว่า handler ไม่มีอยู่ที่อื่น
- การทดสอบ `server/image-relay-flow.integration.test.mjs` จำลองการจับคู่ การส่งต่อด้วย HMAC การเข้าคิว การส่ง FCM การใช้ลิงก์ดาวน์โหลดรูปจาก LINE และการส่งเหตุการณ์ซ้ำ โดยไม่เรียก Thunder; LINE, FCM, Queue และ KV เป็นตัวจำลอง ไม่ใช่การทดสอบมือถือหรือบริการจริง
- Server tests ผ่าน 35 รายการในเครื่อง ณ วันที่ตรวจ

## สิ่งที่ต้องมีเพื่อทดสอบระบบจริง

1. ระบุที่ตั้งหรือผู้ดูแล Webhook LINE OA เดิม ตรวจการรับ `messageId` และเพิ่มการส่งต่อที่ลงลายเซ็นโดยคง URL เดิม
2. ตั้งค่า LINE Channel Secret และ Access Token, Firebase service account, `DEVICE_PAIRING_SECRET`, `IMAGE_LINK_SECRET` และ `FORWARD_SECRET` ในที่เก็บ Secrets ที่เหมาะสม โดยไม่ใส่ค่าลง repository หรือ log
3. ตรวจ Firebase Android build configuration, ติดตั้ง APK ที่กำหนดค่าแล้ว และจับคู่อุปกรณ์
4. ตรวจการ deploy เวอร์ชัน Worker ที่รองรับ image relay และเปิด `SLIP_PROCESSING_MODE=image_relay` หลังเตรียมวิธีย้อนกลับและยืนยันผลกระทบ โดยไม่ส่งสลิปไป Thunder ซ้ำ
5. ทดสอบสลิปที่ได้รับอนุญาตตั้งแต่ LINE OA → Webhook → Queue → FCM → vivo แล้วบันทึกผลจริง การตอบรับ FCM ไม่เท่ากับโทรศัพท์ได้รับหรือพูดสำเร็จ

ยังไม่มีการเปลี่ยน Webhook, Secrets, Worker หรือการตั้งค่า production จากการตรวจนี้
